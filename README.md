# 蚕CHANNEL 体長チェック・試作版

Windows 11向けの、ローカルで動く無料のPythonアプリです。映像や測定データを外部に送信しません。初回のライブラリ導入時だけインターネットを使います。PHP、クラウド契約、APIキーは不要です。

**この版は撮影環境を確認するための試作です。** 通常は色と形を使う画像処理です。追加セットアップで、PC内で動くMobileSAMによる領域分割も使えます。共有された5齢の画像で改善を確認しましたが、蚕専用の学習済み検出器ではなく、各齢・別の撮影条件での認識精度は未検証です。候補には体の一部分や誤検出も含まれます。

AI版を初めて試す場合は [AI_QUICKSTART.md](AI_QUICKSTART.md) の手順を使ってください。

## 最初の起動

1. [Python公式サイト](https://www.python.org/downloads/windows/)から、**Python 3.12の64bit版**をインストールします。インストーラーではPython LauncherとTcl/Tk（通常の標準構成）を含めてください。すでに3.12があれば不要です。
2. ZIPを右クリックして「すべて展開」します。書き込み可能な場所に置いてください。ZIPの中から直接起動しないでください。
3. `setup_windows.bat` をダブルクリックします。ライブラリをダウンロードするため、初回は少し時間がかかります。
4. 「Setup complete」が出たら `start_windows.bat` をダブルクリックします。以降はこのファイルで起動します。

AI版は `setup_ai_windows.bat` が通常分もまとめて導入するので、別に `setup_windows.bat` を実行する必要はありません。

初めに表示されるのは合成のデモ画像です。緑の測定候補2つと、橙の交差領域1つを確認できます。デモの自動測定はCSVに記録しません。デモが動くことと、実際の蚕を正確に測れることは別の確認です。

exe形式ではありません。問題が起きたら、表示されたエラー文をそのまま教えてください。

## まずは画像や短い録画で試す

「画像／録画を開く」から、蚕が映るPNG・JPEG、またはOBSで保存したMP4・MKV等を開きます。右側の温湿度表示も入った映像で構いません。「測定範囲を2点指定」で、蚕の容器だけを囲みます。配信UI、定規、白い壁などはできるだけ外します。

共有いただいた5齢のOBS配置では「主映像：左77%」、1齢・2齢の配置では「主映像：左2/3」が範囲設定の目安です。右の温湿度UIや別カメラ映像を外すためのプリセットです。齢から配置を自動判定する機能ではありません。範囲の設定後は一時停止しているので、枠を確認して再生してください。別の配置・Webカメラ単独の映像には手動の範囲指定を使います。YouTubeのページ全体、再生バー、重なったメニューは自動除去しないため、OBSの元映像を推奨します。

「試験的な候補抽出」で「明るい蚕」「暗い蚕」を選び、「検出設定を適用」を押せます。1齢の共有画像では暗く、2齢では明るく見えるため、齢だけで設定を固定せず映像に合わせて選択します。明るさ境界は、明るい蚕では下限、暗い蚕では上限として使います。暗い葉・影・葉脈・排泄物も候補になり得る基本的な抽出であり、この切り替えだけで各齢の検出精度が確認されたわけではありません。

自動検出が難しい画面では「手動で体長をなぞる」を使います。頭の先から尾の先まで、体の中央を曲がりに沿って順番にクリックし、「手動測定を確定・保存」を押します。曲がりの強い所は点を増やしてください。隠れた部分を推測でつなぐと、正しい全長になりません。

**自動測定の緑の線が、実際の蚕1匹の頭から尾までをたどっているか確認してください。** 葉、葉脈、白い発泡スチロール、部分的に見えた体が候補になる場合があります。橙の領域は集計から除外しています。除外領域の個数は、測れなかった蚕の匹数ではありません。

## mmに換算する

基準を設定するまではpx（画像上の長さ）で表示します。

1. 蚕とおおむね同じ高さに、定規など長さの分かる物を置きます。
2. 「基準線を2点指定」の右に、実際の長さ（例：10mm）を入力します。
3. 映像内でその区間の両端をクリックします。長めの区間を使うと、クリック位置の誤差の影響を小さくできます。
4. 再生ボタンで自動測定に戻ります。基準線・範囲の指定中は一時停止します。

カメラの位置、ズーム、OBSでの拡大率、容器・葉の高さを変えたら基準を設定し直します。入力の変更や映像の解像度変更では基準を自動解除します。基準は再起動時に引き継ぎません。葉が高く積まれた部分や持ち上がった頭には、高さによる換算誤差が生じます。

目印が置けない場合でもpxで試せます。ただし、カメラや映像の倍率が変わると過去のpx値とは直接比較できません。

## LIVEで使う

**OBSがWebカメラを使用している場合は、OBSの仮想カメラを入力にする方法から試します。** 実際のWindows環境・ドライバーでの同時動作確認はこれからです。

1. OBSで通常の配信画面を用意し、「仮想カメラ開始」を押します。
2. このアプリでカメラ番号0、1、2…を試し、OBSの映像が出る番号で接続します。番号とカメラの対応はPCによって異なります。
3. 蚕の映る部分だけに測定範囲を設定します。温湿度UIや、このアプリの結果表示は範囲に含めないでください。
4. 基準線を設定し、再生します。

Webカメラを直接使う場合もカメラ接続ボタンを使います。OBSと同じ物理カメラを両方から開けない機種があります。カメラが出ない時は、Windowsのプライバシー設定でデスクトップアプリのカメラアクセスも確認します。

YouTube URLを直接入力する機能はありません。YouTubeの圧縮・遅延を避け、PC内の映像を使う構成です。通常配信への影響を確認するため、まず配信せずにOBSの録画・仮想カメラで試してください。

自動解析はおおむね0.5秒間隔を目標にします。処理速度はPC性能、解像度、領域の複雑さによります。全30匹を検出・分離できることを保証するものではありません。

## OBSに数値を表示する

アプリが作る `data/obs_status.txt` を、OBSの「テキスト（GDI+）」ソースの「ファイルからの読み取り」で指定します。日本語フォントを選び、右側の温湿度表示の近くに配置できます。今の温湿度用Python UIのコードを変更せずに試せます。

自動抽出では「自動検出を調整中・蚕の認識は未確認／体長の測定値なし」と出します。葉や背景を蚕と誤認した数値を配信に表示しないため、未確認候補の平均や個数はOBSへ出しません。手動測定を確定した場合は手動の静止値を表示します。アプリの強制終了やPC障害時にはOBS側に最後の内容が残る場合があるため、配信時は動作状態も確認してください。

既存の温湿度用Python UIに組み込むには、そのUIのコードと映像の受け取り方を確認してから調整します。

## 保存・平均の推移

- `data/measurements.csv`：自動は約10秒ごと、手動は確定時に追記します。CSVはExcelでも開けるUTF-8 BOM付きです。保存できない時は、Excelで開きっぱなしになっていないか確認してください。
- CSVには測定時刻、入力、録画内の秒数、単位、各候補の長さ、平均、最小、最大、基準、範囲、検出設定を記録します。このアプリは元の動画を常時保存しません。検証画像は下記のボタンを押した時だけ保存します。
- `method=auto_candidate` は色と形、`method=sam_auto_candidate` はAIによる未確認候補の記録です。蚕の確定した測定値として扱わないでください。`method=manual` は手動測定です。手動結果は候補の集計に混ぜません。旧版の `method=auto` 行も未確認候補であり、正解の測定値ではありません。
- グラフはこの起動中・同じ設定の候補線の平均長を、最大600記録（連続測定なら約100分）表示します。蚕の平均体長・成長率を表すグラフではありません。基準・範囲・検出設定・入力を変えるとグラフをリセットします。CSVの過去行は残ります。
- CSVの時刻は実行PCの現地時刻とUTCオフセットです。録画を開いた場合は、録画が撮影された過去の日時ではなく、このアプリで測った日時です。
- 番号は各画面内の仮番号です。個体を日ごとに識別したり、同じ蚕の成長を追跡したりする機能はありません。

見える個体が入れ替わると、成長していなくても平均値は変わります。サイズによって隠れやすさが違えば偏りも出ます。将来の成長比較では、毎日同じ撮影条件・時間帯で確認した値を残すなど、測定の条件も揃える必要があります。

## 元映像から検証画像を保存する

「検証画像を保存」を押すと、現在の測定範囲を元の画素のままPNGで `data/samples/` に保存します。プレビューの縮小や緑の候補線を重ねる前の画像です。基準・範囲・検出設定・録画内の秒数等を、同名のJSONファイルにも保存します。ネットへの送信は行いません。

この機能は、蚕と誤検出の例を元画質で確認するためのものです。自動候補を正解ラベルとして扱いません。蚕専用の学習をする場合には、別途、人が正しい体の範囲を指定したデータと、評価用の映像が必要です。今回のスクリーンショットだけで学習や精度検証が済んだわけではありません。

## 自動検出の調整と限界

「明るさ下限」を上げると明るい部分だけ、「彩度上限」を下げると白っぽい部分だけを抽出します。「検出マスク表示」で白く残っている所が検出対象です。面積の値は元映像のpx²です。「細長さ下限」は丸い物などの除外に使います。各値は入力後に「検出設定を適用」を押してください。

枝分かれ・輪・画面や測定範囲の端に触れる候補などは除外します。ただし、重なりが必ず枝分かれになるとは限りません。**葉で隠れた体や、枝分かれせずに重なった2匹を、自動で確実に見抜ける版ではありません。** 部分的な体が測定候補として残る場合もあります。画像処理で分かる範囲の選別です。

蚕と発泡スチロールが同じように白い条件では、しきい値調整だけで対応しきれない可能性があります。次の段階は、実際の撮影画像を見て、背景の条件調整・手動補助・必要に応じた蚕専用の学習のどれが有効かを決めることです。

## 追加のAI領域分割

`setup_ai_windows.bat` でCPU版の追加ライブラリと公式モデルを導入します。初回は数百MB規模のダウンロードがあり、時間がかかります。以降の解析はPC内で行い、画像を外部サービスへ送りません。モデルは公式リポジトリの固定コミットとSHA-256で確認します。

「AIでこの画面を解析」は現在の画像・映像を一時停止して1回解析します。「AIで映像を繰り返し解析」は、カメラ・録画から処理可能な頻度で新しいフレームを解析します。画面は**最後に解析した静止フレーム**であり、処理中の最新のカメラ映像ではありません。結果と異なるフレームに輪郭を重ねないための仕様です。入力・範囲・基準が変わった場合は、古い処理結果を捨てます。

モデルが出したマスクごとに、色・面積・中心線の形・境界への接触を確認します。同じ体の内側の重複領域や、候補群に対して極端に細い領域も除外します。これは候補を減らすための仮の絞り込みです。異なる大きさの蚕が混在する場合には、小さい個体を除外してしまう可能性があります。

AIの場合、明るさ・彩度の設定は**領域全体の中央値**に適用します。色と形の方式のように、個々の画素をしきい値でつなげるものではありません。黒い余白を除いてから解析し、その境界で体が切れた候補を除外します。**重なりや葉で隠れた部分の全長を確定する機能はありません。** 体の部分領域が候補として残る場合があります。

共有画像1枚（1478×1080、5齢）を組み込んだ処理で実行すると、18本の候補線が残り、複数の蚕の輪郭を追えることを目視で確認しました。18匹を正しく数えたという評価ではありません。部分的な体の候補や見逃しがあり、正解の全長・mm換算・検出率は検証していません。この画像にはmm換算の基準もありません。

開発環境のCPU（3スレッド）で、この画像のAI処理は約46秒でした。通常の色抽出とは速度が大きく異なります。利用PC、GPU、解像度等で変わるため、リアルタイムの速度は保証しません。GPU版は `setup_ai_gpu_windows.bat` でCUDA 12.8版PyTorchを入れる選択肢がありますが、対応するNVIDIAドライバーが必要で、Windows/GPUの実機検証はまだ行っていません。まずはCPUで静止画の結果を確認してください。

AIの候補も未確認として扱い、OBSには候補数・平均を測定値として出しません。単発AI解析は完了時、繰り返しAI解析は10秒以上の間隔で完了時に、未確認候補としてCSVに保存します。

[MobileSAM公式ソース](https://github.com/ChaoningZhang/MobileSAM)の固定コミット `f706ad9c4eb7f219c00d9050e46328518ffb65d2` を使います。MobileSAMはApache License 2.0、その他のライブラリはそれぞれのライセンスです。

共有された2枚の画面を目視で確認すると、蚕が白い背景に接する箇所、重なって頭や尾が隠れる箇所、画面端で途切れる個体があります。色だけで切り出した領域を1匹の全身と見なすことはできません。今回追加した配置プリセットは集計範囲を直すもので、これらの検出精度を改善したものではありません。画像内に長さの分かる基準がないため、実際の体長をmmで読み取ることもできません。

## 検証したこと

LinuxのPython 3.12で26件の自動チェックを実行しました。曲線の長さ・基準換算・境界で切れた体の除外・CSV/OBS出力・録画読み込みなどに加え、白い背景と独立したマスクからの計測、重複候補の除外、画像座標の復元、処理待ちキューの制限、古い入力の結果を捨てること、解析したフレームへの描画を確認しています。

共有された実画像1枚について、従来法と追加AIの両方を実行し、結果を目視で比較しました。これは撮影条件全体の精度評価や、実際のmm単位の体長の検証ではありません。通常版の主要依存ライブラリのWindows 64bit/Python 3.12用wheelの取得も確認しました。

**Windows実機、実カメラ、OBSとの同時動作、実際の蚕の測定誤差、画面操作は未検証です。** 合成画像のテスト結果から、実際の蚕の精度を保証することはできません。

手動でチェックを実行する場合：

```bat
.venv\Scripts\python.exe -m unittest -v
```
